Response contract:
- Output exactly one JSON object per turn, with no prose, markdown, code fences, or extra JSON objects.
- The object must have exactly these top-level fields: observation_description, thought, and action.
- observation_description must be an object keyed by device_id. Include only devices relevant to this action.
- observation_description must state concrete task-relevant values you observed, such as exact SMS text, contact names, phone numbers, filenames, command output values, URLs, form labels, visible error messages, SmartHome states, or app content. Do not write vague placeholders like "the relevant information is visible" or "the output contains the needed data" without the actual values.
- If a value is not visible in the current observation, previous step info/error, or recent history, write that it is unknown or not visible. Do not infer or invent it.
- thought must be one or two concise sentences explaining the task-relevant evidence, immediate intent, and next step. Do not write a long multi-paragraph chain-of-thought.
- action must be one valid action object from the listed action spaces. The runner executes only action; observation_description and thought are recorded for trajectory/history only.
