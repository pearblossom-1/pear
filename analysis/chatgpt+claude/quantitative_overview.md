## 4. 行为信号（不是原因分布）

来源为 [behavioral_signal_counts.csv](/Users/lht/home/MDCBench/analysis_phase1/behavioral_signal_counts.csv)。均按“有此现象的任务数”而不是错误 step 次数计数，可重叠。

| 信号 | GPT 原始失败 N=143 | Claude 原始失败 N=125 |
|---|---:|---:|
| 出现任意 explicit feedback error | 60 (41.96%) | 82 (65.60%) |
| 出现模型 action envelope 错误 | 29 (20.28%) | 54 (43.20%) |
| 出现明确 action timeout | 16 (11.19%) | 1 (0.80%) |
| 完全相同 action 至少 3 次 | 60 (41.96%) | 64 (51.20%) |
| 某失败条件的设备没有被选择行动 | 12 (8.39%) | 17 (13.60%) |

GPT 12 个原始 PASS、Claude 16 个原始 PASS 也有 explicit feedback error。因此 presence of error 不是失败原因，也不等于没有恢复能力。另有 GPT 83/143、Claude 43/125 原始失败没有此类显式反馈错误，失败可能发生在被接受的动作、源选择、遗漏或评分契约上。

全体有效运行中，GPT 17/200 出现明确动作 timeout，Claude 1/200。GPT 这 17 条均涉及 Android 执行/ADB input 路径；Claude 的 1 条是 linux_android_1869 的 Linux CLI timeout。两个模型遭遇的中途执行层问题不完全相同，这是需核对设备/批次条件的混杂因素，不能直接推断模型架构差异，也不能把 17 条全部改算环境失败或直接扣除。

device-switch 平均数为 2.01 与 2.22；更多切换不必然更差。未选择某 evaluator device 也不必然遗漏：初始状态可能已满足，或该条件就是要求不修改。没有因果精读前，这些只作检索线索。

## 5. 使用边界

每模型每任务只有一个选用的有效尝试，不从本地数据宣称统计显著性、架构原因或跨全部 baseline 的通用结论。原始 result 表、人工复核表和待复核疑点始终分开；未完成因果精读的标签不用于 prevalence 分布。
