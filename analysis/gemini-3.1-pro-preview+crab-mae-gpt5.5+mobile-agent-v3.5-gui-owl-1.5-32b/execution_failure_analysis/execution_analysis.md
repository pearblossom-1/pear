有效运行在这里定义为：正式汇总选中、记录为completed且有对应结果与历史任务/evaluator材料。不是“已经人工审计无任何环境问题”。三组各200条completed、无缺失选中结果；各summary记录active_incomplete=0。归档中断记录不重复计入。

统计集合仍是每组全部200条。duration直接取 `result.json.duration_s`；保存的timings表明它是包括环境启动、reset、请求、动作、评估、cleanup等阶段的总时长，不是纯模型思考时间，更不是失败恢复所耗费的全部实验日历时间。各run_metadata记录max_steps=50、max_duration_s=1800、process_timeout_s=2100。

终止方式直接读取显式字段；600条中summary与raw的termination_reason无冲突，time_limited与time_limit无冲突，显式max_steps的步数均为50。**done不是成功标签，也不一定是模型主动完成**：M2的done由协议错误阈值触发。completed记录里returncode=1与FAIL共491条，不能据此写成491次runtime崩溃。本表没有把自动failure_category统计成原因分布，也没有把超时推断成循环。

## 5. 定性案例与能支持的机制

本轮核实六个失败案例，精读两条成功对照；另外四条筛查记录排除。各案例保留完整动作序列检查、关键历史观测及恢复情况，详见 [failure_cases.md](failure_cases.md)。这是12条定向筛查记录的覆盖说明，不是总体失败分布，也没有独立人工一致性统计。

| 可观察机制/现象 | 支持案例 | 关键依据与限制 |
|---|---|---|
| 指定对象绑定错误，局部成功不等于任务成功 | G1、C1；成功对照S2 | G1实际打开错误笔记并转换其正文；C1调暗另一盏灯。C1是同Home内家电错选，不是跨实例路由错误。 |
| 重复失败的执行回路没有形成有效修正 | M1；成功对照S1 | 取得三条CSV后49次转换报SyntaxError，其中后48次命令完全相同。不能归为纯跨设备数据传递失败；内外层ok不同，不能断言模型看到了完整stderr。 |
| 正确子目标/操作意图没有成为合法可执行动作 | C2、M2 | C2在Home反复输出双动作，被每环境每轮一个动作的协议拒绝；M2缺少type文本参数，最终由适配器结束。属于当前模型+框架+适配部署的系统现象，不单独归咎于基础模型。 |
| 局部GUI输入恢复，最终提交仍未落地 | G2（附录） | 最终字段已正确，但最后点击落在按钮之外。早期输入问题已经恢复，不能拿它冒充最终失败原因。 |

正文优先G1、C1、M1、C2；附录保留G2、M2。S1只说明相同任务存在成功写入路径；S2展示保留准确目标并报告不可行的完成方式。对照不能替代失败run本身的历史证据。

材料不支持“所有失败都是协调问题”、某机制最常见、某模型更易出现某类原因、memory/planner/verifier已被证明有效。没有统一可比的Diagnostic阶段材料被采用，故不把Core200成功率与另一批Local-All作差，也不从partial score解释全部Composition Gap。当前证据已足够支撑有限正文，不要求其他机器补满分类或精读剩余失败。

## 6. 具体缺口和少量疑点

X1（G / linux_only_249）：历史命令修复ASCII审批码规则，测试输出明确为`12 passed`而自动FAIL/0；无独立失败证据，暂不作为能力案例。

X2（G / linux_android_1320）：历史最终文本已经阻止芝麻过敏冲突的配方，订单文件不存在，但自动score=0.5；命名/短语要求相关疑点未展开。两条都只记录事实，不执行新裁决。

X3（C / study_focus_sequence）：最初多动作拒绝后来恢复，已建立两个正确时间的计划；未来亮度动作是否还实现开灯没有独立回读支持，不用早期错误归因。X4（C / linux_smarthome_028）：要求的计划确已取消，额外家电修改触发保护检查；范围解释不够干净，不作正文必要目标失败证据。

其他限制：没有每个API请求的完整历史输入体；不从执行日志反推模型一定看到了某条信息。共享cache内当前产物不作为原attempt证据。服务端模型身份只沿用已有元数据声明。以上均不阻止六条明确案例的分析，也不说明未审计的evaluator没有问题。

## 7. 交付与复核方法

- [execution_results.csv](execution_results.csv)：600行，一行一个正式selected attempt；包含raw/adopted结果、分数、步数/时长/终止标志、实例/类型、全部来源引用、案例采用/排除说明。

- `analyze.py`与`aggregate_support.json`仅为轻量离线解析及可复核统计支撑，不是新的benchmark运行或评分流程。
